# Релиз: как это делается на самом деле

Три репозитория (`dark-omens`, `dark-omens-relay`, `dark-omens-admin`) выпускаются
вместе и оркестрируются **корневым Makefile** в `godot_projects/`. Запускать из
Git Bash: в cmd нет `sh`, и часть целей туда не переносится.

> **Makefile не под гитом.** Воркспейс `godot_projects/` — не репозиторий, цели
> живут только на рабочей машине. Поэтому здесь описаны и команды, и то, что за
> ними стоит: на новой машине придётся восстанавливать руками.

> **Godot не в PATH.** Всем игровым целям нужно передавать путь:
> `make game-export GODOT='C:/Users/fatuk/Godot/Godot_v4.6.2-stable_win64_console.exe'`

## Патч или минор — это разные процедуры

Решается одним вопросом: **менялся ли клиент?**

| | ПАТЧ `x.y.Z` | МИНОР/МАЖОР `x.Y.0` |
|---|---|---|
| Что вошло | только сервер: реле, админка, контент CMS | всё, что трогает игру |
| Версию игры | НЕ трогаем | бампим вместе с реле до одного номера |
| Сборку игры | НЕ делаем | собираем Windows + macOS |
| Тег | только в реле | в игре и в реле |

Правка задела и клиент, и сервер — это **не патч, а минор**: иначе игроки её
просто не получат. Следствие, с которым надо жить: багфиксы в игре не выходят
патчем, они копятся до ближайшего минора.

Расхождение в третьей цифре между игрой и реле — норма.

**Сверки версий в коде НЕТ.** Клиент версию никуда не шлёт, реле её не
проверяет; `config/version` нужен только для надписи на главном экране
(`home.gd`). То есть совместимость держится на этой договорённости, а не на
проверке: при реальном расхождении игрок получит непонятную ошибку, а не
внятное сообщение.

## Порядок минорного релиза

**1. Контент из CMS — в файлы игры.** Если в админке что-то правилось:

```bash
make content-export-dry     # посмотреть, что изменится
make content-export         # записать + переимпортировать проект в Godot
```

Переимпорт обязателен: рантайм читает бинарные `.translation`, а не CSV.
Коммитить нужно и `data/*.json`, и `assets/i18n/translations.csv`, и обе
`.translation`.

**2. Версии — в двух местах.**

- игра: `project.godot`, `config/version` — **через Godot**
  (`set_project_setting`), а не правкой файла: открытый редактор перезатрёт;
- реле: `package.json` + `package-lock.json`, обе строки `version`.

**3. Девлог.** `dark-omens/devlog/<version>.md`, RU + EN — из него берётся пост
на itch.io.

**4. Гейты.**

```bash
cd dark-omens && ./run_tests.ps1     # GUT, вся папка test/unit
make test                            # vitest реле
```

В реле pre-commit сам гоняет `typecheck && test`, так что коммит с красными
тестами туда не пройдёт. В игре такого хука нет — гонять руками.

**5. Сборки.**

```bash
make game-export        # build-win/DarkOmens-<VERSION>.exe, пресет "Windows Desktop"
make game-export-mac    # build-mac/DarkOmens-<VERSION>.zip, пресет "macOS"
```

macOS собирается **с Windows-хоста**: universal (x86_64+arm64), ad-hoc подпись.
Обязательное условие — `texture_format/etc2_astc=true` в пресете И
`import_etc2_astc=true` в проекте, иначе Godot прямо отказывается собирать
arm64. `.dmg` с Windows не собрать (нужен `hdiutil`), отдаём `.zip`; рядом
кладётся `INSTALL-macOS.txt`. Сборка не нотаризована — у скачавшего сработает
Gatekeeper. Подробности: [macos-build.md](macos-build.md).

**6. Теги и пуш.** В Makefile их нет, делаются руками в каждом репозитории:

```bash
git tag v<version> && git push && git push --tags
```

**Пушим все три репозитория — игру, реле и админку.** Это часть релиза, а не
отдельное решение: игра без задеплоенного бэкенда полурабочая. Проверено болью
на 0.4.2 — выкатили клиент, реле осталось локальным, и на проде вместо авторских
встреч Иных Миров игроки получили механическую заглушку, потому что фикс лежал в
неотправленных коммитах.

Вне релиза правило обратное: коммитим локально, **не пушим**.

**7. Деплой.** Реле разворачивается на Render (`dark-omens-backend`) самим
пушем, 1–2 минуты. Проверка — `uptime_s` в `/health` сбросился. Админка и
лендинг — свои сервисы, тем же способом.

**8. Контент на прод — отдельно.** Деплоем он НЕ едет: у прода своя `content.db`.

```bash
make sync-dry     KEY=<ADMIN_KEY прода>   # превью
make sync-content KEY=<ADMIN_KEY прода>   # залить, upsert по id
```

Ключ лежит в переменных Render; в локальном `.env` его нет. Синк не удаляет —
карточка, удалённая локально, на проде останется.

## Публикация сборки — НА ПАУЗЕ

С 2026-08-22 готовятся продажи, и раздавать `.exe` бесплатно больше не хотят.
Речь **только о готовом билде**: код игры пушится в GitHub как обычно.

**`make publish` и `make release` не запускать.** Они пушат сборку в
`old-ones/dark-omens:windows` через butler, то есть выкладывают игру людям.
butler лежит в `/c/butler/butler` и уже авторизован — тем более не трогать без
явного решения.

## Порядок патча (только сервер)

1. Бампнуть `package.json` + lock в реле.
2. Тег `v<version>` в реле.
3. Пуш реле → Render передеплоит.
4. При необходимости — `make sync-content` для контента.

Версию игры не трогаем, сборку не делаем, в игровой репозиторий не пушим.

## Размер сборки

Замерено на 0.5.0: `.exe` 388 МБ, macOS `.zip` 348 МБ. Основной вес — `assets/`
(~348 МБ, из них `map.png` ~54 МБ на формат). `addons/` весят ~4 МБ и на размер
практически не влияют — исключать их из `export_filter` смысла нет.
