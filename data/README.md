# data/ — что здесь правится руками, а что генерируется

Половина файлов в этой папке — **сборочные артефакты**. Открыв их в редакторе,
это не видно никак, поэтому список здесь.

## Генерируется из CMS — руками НЕ править

Источник правды — админка (`dark-omens-admin`, корпус в реле). Правка прямо в
файле проживёт до следующего экспорта и молча исчезнет.

| Файл | Тип в CMS |
|---|---|
| `investigators.json` | `investigator` |
| `assets.json` | `asset` |
| `spells.json` | `spell` |
| `monsters.json` | `monster` |
| `artifacts.json` | `artifact` |

Особый случай — **локации**. `locations.json` правится руками (см. ниже), но его
ТЕКСТЫ (название, реальное место, описание — 108 ключей `LOC_*`) живут в CMS в
карточках типа `location`. Экспорт забирает оттуда строки переводов и **не
трогает сам JSON**: граф доски остаётся в файле.

Плюс к ним — строки переводов в `assets/i18n/translations.csv`: у каталогов там
свои ключи (`ASSET_*`, `ARTIFACT_*`, `INV_*`…), их экспорт тоже переписывает.

Как обновить после правки в админке — из корня воркспейса:

```bash
make content-export-dry   # посмотреть, что изменится, ничего не трогая
make content-export       # записать + сразу переимпортировать проект в Godot
```

Переимпорт входит в цель намеренно: рантайм читает бинарные `.translation`, а не
CSV, и без него правка текстов в игре не появится. Отдельно скрипт зовётся так:
`cd ../dark-omens-relay && npx tsx scripts/export-game-content.ts [--dry]`.

Правка в админке САМА в файлы не попадает — админка пишет только в базу. Пока не
прогнал экспорт, игра читает старое. Весь порядок выпуска — в
[docs/release.md](../docs/release.md).

## Служебный флаг `isReady`

`data.isReady` — ручная отметка автора: карточка полностью готова после
редактуры. Ставится только руками в админке: колонка «Готово» в списке
(сохраняется сразу, есть фильтр «не готовые» и сортировка, которая поднимает
неготовые наверх) и галка «готово» в редакторе. Нет поля — карточку ещё не
отмечали, это то же «не готово». Игра флаг не читает.

До 2026-10-18 флаг назывался `hasImage` и у каталогов с покарточным артом
вычислялся по файлам; при переименовании те значения убраны (они были про
картинку, а не про готовность), ручные галки встреч/Тайн/Мифов перенесены.

### Отчёт по арту

Есть ли у карточки картинка в игре — флагом больше не хранится. Отчёт только
печатает, в карточки ничего не пишет:

```bash
make content-images   # где арта нет и где имя файла не совпадает
```

Игра ищет файл строго по имени из `String.capitalize()` Godot
(`colour_out_of_space` → `Colour Out Of Space.png`). Файл с другим именем
движок не найдёт, поэтому отчёт отдельно печатает «почти совпадения» — это не
«арта нет», а «арт есть, но назван так, что игра его не подхватит».

## Правится руками здесь

`locations.json` · `conditions.json` · `action_log.json` · `messages.json` ·
`stoic_quotes.json`

`locations.json` — только СТРУКТУРА: связи, координаты, тип клетки и ключи
переводов. Сами тексты по этим ключам правятся в админке (см. выше). Плюс файл
ещё и **источник** для реле: `scripts/bake-locations.cjs` собирает из него
`config/locations.json`. Направление обратное экспорту, не перепутать.

Добавляя локацию, нужно сделать ДВА шага: запись в этом файле (структура) и
карточку `location` в админке (тексты). Забудешь второй — на карте будет виден
сам ключ; это ловит `test_location_text_keys_are_translated`.

## Почему сгенерированное всё-таки лежит в гите

Обычно генерируемые файлы в репозиторий не кладут. Здесь наоборот, и причин три.

**Это формат поставки.** Игра читает каталоги из `.pck`, живой подгрузки нет
(см. ниже). Без файлов в дереве сборку просто не из чего собрать.

**Это единственная версионированная копия контента.** Корпус CMS живёт в
docker-томе `dark-omens-relay_db_data`, в гит он не попадает — ни дампом, ни
сидом. То есть `data/*.json` плюс `translations.csv` и есть история контента:
именно по их диффам видно, что поменялось в карточке.

**Это же и путь восстановления.** Конвейер двусторонний:

```bash
npx tsx scripts/export-game-content.ts   # CMS  → файлы
npx tsx scripts/import-game-content.ts   # файлы → CMS   (идемпотентно)
```

Новый каталог обязан быть заведён в ОБОИХ скриптах: экспорт без импорта означает
контент, который некому восстановить.

Импорт — аварийный путь: он вернёт каталоги, но не встречи, Мифы, Тайны и
Древних (их в файлы игры не экспортируют). Штатный способ пережить потерю тома —
снимки базы, `npm run db:backup` в реле; см. `dark-omens-relay/docs/backups.md`.

Если корпус когда-нибудь начнёт версионироваться сам (коммит дампа или сида),
эти файлы можно будет унести в `.gitignore` — но не раньше.

## Почему каталоги не тянутся с сервера в рантайме

Живая подгрузка ломала бы офлайн и детерминизм партии, а главную выгоду —
«контент без новой сборки» — всё равно съедает арт: портреты и карточки лежат
в `.pck` и без обновления клиента не приедут. Поэтому каталоги едут в сборке.

С сервера в рантайме приходит другое: Древний, его Тайны, карты Мифов и
встречи. Отсюда и правило версий — сезон из одних Древних выпускается патчем,
а сезон с новыми сыщиками или предметами требует обновления клиента.
